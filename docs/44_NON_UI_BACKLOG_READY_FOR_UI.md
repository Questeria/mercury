## UI Security Rules

- Enable UI actions from capability booleans, not from raw reason codes.
- Display `reason_label` and stable labels; do not map numeric codes in UI code.
- Keep message UI closed unless bootstrap exposes `can_open_message_ui = true`.
- Keep local decrypt closed unless bootstrap exposes `can_decrypt_local_store = true`.
- Do not store plaintext messages, media, prompts, AI transcripts, or identity material in UI state that can persist across restarts.
- Treat AI as an explicit participant with visible grant state.
- Use `local_ai_draft_assist` only for draft assistance. It cannot run backend sessions and does not emit a session event stream.
- Use `ai_connector_*` prototype fixtures before wiring any model runtime; the accepted connector path can emit drafts only and still requires user review.
- Use `account_recovery_*` prototype fixtures before showing recovery as actionable; never implement low-entropy recovery or plaintext backup paths in UI code.
- Use `group_chat_*` prototype fixtures before opening group chat, enabling group sends, or allowing membership changes; high-security group UI must require MLS readiness, accepted provider security, and `requires_pq_upgrade = false`.
- Use `group_message_transcript_*` prototype fixtures before wiring group send persistence or relay-submit states; transcript UI must route `requires_sync` to sync and `requires_rekey` to rekey/remediation, never plaintext fallback.
- Use `anonymous_credential_issuer_trust_*` prototype fixtures before exposing anonymous credential issuer diagnostics; UI must treat transparency, witness/auditor, revocation, and partitioning-metadata failures as backend security blocks.
- Use `anonymous_group_membership_proof_*` prototype fixtures before exposing proof diagnostics; UI must not infer anonymous membership from route ids, member names, or local room caches.
- Use `anonymous_rate_limit_nullifier_*` prototype fixtures before exposing anonymous abuse-control diagnostics; UI must not bypass replay, exhausted-window, or nullifier-store failures.
- Use `anonymous_nullifier_store_*` prototype fixtures before exposing nullifier persistence diagnostics; UI must not treat a stored duplicate or plaintext metadata rejection as recoverable send state.
- Use `mls_provider_evidence_store_*` prototype fixtures before exposing MLS provider validation diagnostics; UI must not treat rejected provider evidence, duplicate evidence, or plaintext evidence as recoverable group state.
- Use `mls_provider_evidence_use_*` prototype fixtures before treating stored provider evidence as current; UI must not open group readiness from missing, expired, suite-mismatched, or plaintext-tainted evidence.
- Use `mls_key_package_admission_*` prototype fixtures before exposing group invite or add-member readiness; UI must not enable membership changes or Welcome sending from rejected KeyPackages.
- Use `mls_key_package_consume_store_*` prototype fixtures before enabling Welcome send from an accepted KeyPackage; UI/backend code must not send a Welcome unless accepted KeyPackage admission and accepted consume-store persistence both succeed.
- Use `mls_welcome_send_outbox_*` prototype fixtures before treating a Welcome as queued for delivery; UI/backend code must not send inline outside the accepted outbox path or retry a duplicate Welcome-send transaction as a new send.
